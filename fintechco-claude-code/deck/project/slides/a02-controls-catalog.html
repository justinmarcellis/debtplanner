Sources: [CLM-677] [CLM-679] [CLM-689] [CLM-684] · example policy: demo/enterprise/managed-settings.json

If asked what exactly the policy can enforce: deny rules for secrets and pushes; disabling the bypass mode; allowing only approved hooks [CLM-677]; an OS sandbox, off until the policy switches it on, that limits which domains shell commands can reach; an allowlist of approved MCP connections [CLM-679]; approved models and version floors, which on Bedrock and Google Cloud are set through these managed settings [CLM-689]; and the telemetry exporters, which only take effect from managed or user settings, not from a repository file [CLM-684]. The demo kit includes an example policy file.
